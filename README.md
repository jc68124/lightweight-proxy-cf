# Lightweight Proxy for Cloudflare Workers

A small, framework-independent reverse proxy using **Cloudflare Service Bindings**. One public Worker routes to independently deployed web/API Workers. Zero runtime dependencies; native Workers Requests, Responses, and streams.

The browser reaches the public gateway, which forwards through a configured Service Binding to the web or API Worker.

The package has no authentication: no reserved paths, sessions, OAuth, user headers, database bindings, or role checks. `/api/auth/*` is an ordinary route owned by your API.

## Install and use

Once published:

```sh
pnpm add @jc68124/lightweight-proxy-cf
```

Before publication, build and pack this repository and install the resulting tarball (see Verification). Consumers need Workers runtime types, normally generated by `wrangler types`.

```ts
import { env } from "cloudflare:workers";
import { createProxy } from "@jc68124/lightweight-proxy-cf";

export default createProxy({
  routes: [{ match: { prefix: "/api" }, service: env.API }],
  fallback: env.WEB,
});
```

Consumer `wrangler.jsonc`:

```jsonc
{
  "name": "my-gateway",
  "main": "src/index.ts",
  "compatibility_date": "2026-10-28",
  "services": [
    { "binding": "API", "service": "my-api" },
    { "binding": "WEB", "service": "my-web" }
  ]
}
```

Worker names, account configuration, domains, and deployment choices stay in your application. The package never calls global `fetch()` or derives a destination from request input. Only explicitly configured binding objects are called. Pass real Service Bindings; the structural `Service` type only requires their `fetch` method.

## Routing

```ts
createProxy({
  routes: [
    { host: "ingest.example.com", match: { prefix: "/" }, service: env.INGEST },
    { match: { exact: "/health" }, methods: ["GET", "HEAD"], service: env.API },
    { host: "app.example.com", match: { prefix: "/api" }, service: env.API },
    { match: { regex: /^\/v[12]\/reports(?:\/|$)/ }, service: env.REPORTS },
  ],
  fallback: env.WEB,
});
```

- Ordered **first match wins**. Host, path, and method conditions must all match. There is no specificity sorting.
- Exactly one of `exact`, `prefix`, or `regex` is required per rule.
- `host` is optional and matches the URL hostname case-insensitively, ignoring the request port and a final DNS dot. Supply an ASCII/punycode hostname without scheme, port, or path. No host wildcards or host regex.
- Omitted `host` matches all hostnames reaching the Worker. The fallback is global, including for unmatched hosts. For a closed host allow-list, omit fallback and give each host explicit rules.
- Omitted methods allows all methods. Method tokens are case-insensitive; empty arrays are rejected. GET does not implicitly include HEAD. A method mismatch proceeds to later rules/fallback, not an automatic 405.
- Matching reads the runtime URL pathname, not query strings. The proxy does not decode it again, collapse slashes, change case, or redirect. The URL/runtime may already have normalized input before the proxy sees it.
- Regex uses native `RegExp.test(pathname)`. Anchor it yourself if needed. `g` and `y` are rejected to avoid stateful matching. Regex is trusted developer configuration; use bounded, efficient expressions.
- Configuration is compiled and snapshotted at construction. Replace the proxy to change rules; do not mutate configuration to change a running proxy.

| Match | `/api` | `/api/` | `/api/users` | `/apix` |
| --- | --- | --- | --- | --- |
| `{ exact: "/api" }` | yes | no | no | no |
| `{ exact: "/api/" }` | no | yes | no | no |
| `{ prefix: "/api" }` | yes | yes | yes | no |
| `{ regex: /^\/api\/?$/ }` | yes | yes | no | no |

Prefix configuration ignores trailing slashes: `/api/` behaves like `/api`. Prefix `/` matches every pathname. Forwarded paths retain their incoming trailing slashes.

## Forwarding contract

Requests retain their public URL, path, query, method, body stream, and application headers, including Cookie, Authorization, browser Origin, content types, and framework headers. Redirect mode is explicitly `manual`: downstream redirects go back to the browser, without a proxy request to the redirect target.

The proxy passes the original upstream Response through, preserving status/statusText, headers, separate Set-Cookie headers, SSE, streamed HTML, and the Workers WebSocket upgrade response. It does not call `.text()`, `.json()`, clone/tee bodies, or buffer them. WebSockets stay owned by the downstream Worker; the gateway does not accept them or implement a frame relay.

### Forwarding headers and trust

Before forwarding, remove incoming `Forwarded`, **all** `X-Forwarded-*`, and `X-Original-URL` values. Then set:

| Header | Source |
| --- | --- |
| `Host`, `X-Forwarded-Host` | `new URL(request.url).host` |
| `X-Forwarded-Proto` | URL scheme without `:` |
| `X-Forwarded-Port` | Explicit URL port, otherwise 443 for HTTPS / 80 for HTTP |
| `X-Original-URL` | Full incoming `request.url` |

No client-IP chain is synthesized: X-Forwarded-For is removed. Other Cloudflare metadata headers pass through as provided by the runtime, but this package neither verifies nor promotes them to trusted identity. Application-specific headers such as X-User are not authenticated or signed; downstream applications must never interpret them as gateway-authenticated users.

This policy assumes the proxy receives the public request directly. If another Worker constructs a request before invoking it, the proxy can only see that caller's URL; it will not recover an external origin from untrusted forwarded headers. Private downstream ingress prevents browsers from bypassing the policy, but any Worker granted a binding is a trusted caller of that downstream application.

Preserving origin helps downstream frameworks, but applications still own canonical URLs, trusted origins, OAuth callback registration, cookie attributes, and authorization. Wrong application-generated domains are not rewritten.

### Failures

| Situation | Behaviour |
| --- | --- |
| Invalid route configuration | Throws TypeError during construction with a configuration explanation |
| No matching rule and no fallback | `404 Not Found` |
| Selected service unavailable/non-fetchable | `500 Proxy configuration error` |
| Service fetch rejects | `502 Bad Gateway` |
| Upstream returns any HTTP status, including 4xx/5xx | Original response passes through |

Generated errors are plain text with `Cache-Control: no-store`. They do not expose exceptions, binding names, headers, or secrets. There is no diagnostic logging in the package. Inspect application/Cloudflare logs separately. Once a response stream has started, later stream errors propagate as interrupted streams; they cannot become a replacement 502. Failure never retries or selects a second destination.

## Dev container

With Docker and VS Code's Dev Containers extension installed, open this repository and select **Dev Containers: Reopen in Container**. The container provides Node 24 on Debian Bookworm, Git, and pnpm 11.7.0, runs a frozen-lockfile install and package build on creation, and uses the non-root `node` user.

Run `pnpm dev` in the container terminal, then open the forwarded gateway at `http://localhost:8787`. Web/API Workers run behind its Service Bindings. The normal build, typecheck, test, and bundle commands also run inside the container. Rebuild the container after changing its Dockerfile; keep its pnpm pin aligned with `package.json`.

## Runnable example and local development

Requirements: Node 24+, pinned pnpm 11.7.0. Install that pnpm version with your preferred package-manager setup, then:

```sh
pnpm install --frozen-lockfile
pnpm dev
```

This builds the package and launches one command equivalent to:

```sh
pnpm exec wrangler dev \
  -c examples/web-api/gateway/wrangler.jsonc \
  -c examples/web-api/web/wrangler.jsonc \
  -c examples/web-api/api/wrangler.jsonc
```

Open `http://localhost:8787`. Only the first Worker is publicly exposed by this multi-config workflow; the other two are reached through bindings. Cloudflare currently marks this multi-Worker command experimental; this repository pins and verifies its Wrangler version. Run `pnpm dev` again after editing package source to rebuild its exported `dist` files; example Worker edits reload through Wrangler.

Try:

```sh
curl http://localhost:8787/
curl -i http://localhost:8787/api/cookies
curl -i http://localhost:8787/api/redirect
curl -N http://localhost:8787/api/events
curl -X POST --data-binary 'hello' http://localhost:8787/api/echo
```

From the browser console, create `new WebSocket("ws://localhost:8787/api/socket")`; it echoes text/binary frames. The example SSE endpoint is deliberately finite. Longer-lived streams are covered by runtime integration tests.

## Deployment and private downstream Workers

Deploy the target Workers before the gateway on first deployment:

```sh
pnpm build
pnpm exec wrangler deploy -c examples/web-api/web/wrangler.jsonc
pnpm exec wrangler deploy -c examples/web-api/api/wrangler.jsonc
pnpm exec wrangler deploy -c examples/web-api/gateway/wrangler.jsonc
```

Authenticate Wrangler and choose your account in your own deployment environment. The examples contain no credentials, account IDs, database IDs, or production domains. Worker names are example names; rename them consistently before deploying alongside other copies.

Downstream configuration uses `workers_dev: false`, `preview_urls: false`, and no public routes or custom domains. For existing Workers also remove any public routes/domains and preview hosts configured elsewhere. Disabling workers.dev alone does not disable preview/version URLs. Downstream Workers remain callable by explicitly granted Service Bindings. These settings concern public HTTP ingress; other triggers remain application choices.

For production, attach your public hostname to the **gateway**. A Workers Custom Domain is appropriate when the gateway is the origin; Cloudflare handles its DNS/certificate provisioning. Worker routes instead intercept matching requests on a Cloudflare-proxied DNS hostname, often in front of an existing origin. DNS gets the request to Cloudflare, gateway domains/routes select the public Worker, and this package selects an internal binding. Adding a host condition here does not create DNS records or attach that hostname to the Worker.
